# 화학 섬 이야기 (Chemistry Island)

돌턴 박사와 함께 작은 섬을 걸어 다니며 재료를 모으고, 물건을 만들고, 화학 실험을 하는 **탑다운 픽셀아트 생활 시뮬레이션**입니다.
설치 없이 브라우저에서 바로 실행됩니다. (HTML + JavaScript + PNG. 개인 섬은 외부 라이브러리 없이 동작하고, 선택 기능인 공용 광장만 Firebase SDK를 CDN에서 불러옵니다.)

> A cozy top-down pixel-art life sim where you gather, craft and run small chemistry experiments with Dr. Dalton. Runs in any modern browser, no install.

## 바로 플레이

GitHub Pages 주소: **https://juhunbag41-svg.github.io/chemistry-island/**

내려받아 로컬에서 실행하려면 이 저장소를 받은 뒤 `index.html`을 크롬·엣지에서 열면 됩니다. (`assets/` 폴더와 같은 위치에 있어야 합니다.)
이미지가 없거나 불러오지 못해도 기본 도형 그래픽으로 대체되어 게임은 계속 동작합니다.

## 모바일 (휴대전화·태블릿)

터치 기기에서는 자동으로 모바일 화면이 됩니다. 왼쪽 아래 **방향 패드**(손가락을 문질러 8방향 이동), 오른쪽 아래 **행동** 버튼(대화·채집·문·실험대), **가방**, **메뉴**(일지·지도·도움말·저장·전체 화면)를 씁니다. 가로·세로 모두 지원합니다. 주소 뒤에 `?mobile=1` 을 붙이면 모바일 화면을 강제로 볼 수 있습니다.

## 할 수 있는 것

- **탐험:** 숲, 풀밭, 해변, 강, 눈 덮인 연못, 이벤트 광장이 있는 연속된 섬. 낮과 밤, 바람에 흔들리는 풀과 나무, 물결 연출.
- **수집:** 물, 설탕(사탕수수), 소금, 모래, 나뭇가지, 꽃, 얼음, 숨은 연구 노트 조각.
- **제작:** 유리병, 주사기 모형, 연구 노트, 꾸미기 소품(화분, 벤치, 소금 램프).
- **화학 실험:**
  - 요리방 용액 실험대 — 설탕·소금 용액의 **증기 압력 내림, 끓는점 오름**(총괄성).
  - 공방 기체 주사기 — **보일·샤를/게이뤼삭 법칙**, PV = nRT.
  - 공방 기체 혼합기 — **돌턴의 부분 압력 법칙**.
  - 얼음 연못과 소금쟁이 — **수소 결합, 표면 장력**.
- **퀘스트 7개:** 돌턴 박사와 대화하며 재료 수집 → 실험 → 결과 기록 → 보상, 새 공간과 제작법 해금.
- **상점·이벤트·꾸미기·저장:** 재료 거래, 하루 두 개씩 열리는 축제 도전 과제, 섬에 장식 놓기, 브라우저 저장(이어하기).

> 실험 값은 학습용 **이상적인 묽은 용액·이상 기체 모형**의 이론값입니다. 게임 속 ‘스푼’은 물질을 0.1 mol로 맞춰 주는 가상의 도구입니다.

## 오프닝과 시작 튜토리얼

**새로 시작**하면 이름(8자)과 셔츠 색을 정하고, 약 36초의 오프닝 컷신(Esc 또는 화면 위 **건너뛰기** 버튼으로 언제든 건너뜀)이 나옵니다. 샷 3·4에는 그 순간 광장에 접속해 있는 사람이 셔츠 색 실루엣과 이름으로 나오고, 없으면 NPC 실루엣이 나옵니다. 컷신이 끝나면 광장에 도착해 다음 순서로 진행합니다.

1. 숫자 1~8로 이모티콘 인사 (모바일은 ☰ 메뉴의 이모티콘 줄)
2. 돌턴 박사의 입소식 — 중앙 증류솥 끓는점 예측 퀴즈(용질을 넣으면 끓는점 오름, ΔTb = i·Kb·m)와 팀(보일/샤를) 배정
3. 재료 상자에서 기본 키트 받기
4. 남쪽 부두의 배를 타고 내 연구 섬으로 이동 → 돌턴 박사의 첫 퀘스트

### 컷신·시작 화면 이미지

이미지는 ChatGPT 이미지 생성으로 만든 한 장짜리 시안 시트(2026-10-26)에서 칸별로 잘라 쓴 것입니다. 코드는 아래 경로의 파일이 **있고 불러오기에 성공한 것만** 쓰고, 없거나 깨졌으면 코드로 그린 도형 그림으로 자동 대체됩니다(장면·이미지별로 따로). 이미지를 빼려면 파일만 지우면 됩니다.

| 파일 | 쓰임 | 원본 크기 |
|---|---|---|
| `assets/cutscene/shot1~5.webp` | 컷신 1~5번 (밤바다, 이상해진 증기, 연구선 갑판, 새벽의 섬, 일출) | 약 760×340 ~ 600×345 |
| `assets/title/title_bg.webp` | 시작 화면 배경 | 520×345 |
| `assets/logo/logo.png` | 시작 화면 로고 (시트의 체크무늬 배경을 지워 투명하게 만듦) | 362×286 |

원본 해상도가 화면보다 작아서 화면에 맞추려고 늘리면 조금 흐려 보입니다. 더 선명하게 하려면 같은 파일 이름으로 960×600 이상의 개별 생성본을 넣으면 됩니다. 세로 모바일에서는 컷신을 화면 전체에 보여 주고 장면마다 정한 중심 위치(섬)를 가운데로 맞추며, 타이틀 글자는 두 줄로 나눕니다.

세로 모바일에서는 컷신을 화면 전체에 가운데 기준으로 보여 주고, 타이틀 글자는 두 줄로 나눕니다.

**이어하기**는 컷신과 입소식 없이 내 섬에서 바로 시작합니다. 오프닝은 한 번만 재생되며 다시 보기 기능은 없습니다. 레이드는 튜토리얼과 상관없이 누구나 입장할 수 있습니다.

## 공용 광장과 협동 레이드 (멀티플레이)

섬 동쪽 이벤트 광장(다리 수리 후)의 **🌐 광장 포털**로 들어가면 모두가 만나는 공용 광장으로 이동합니다. 광장의 남쪽 부두에서 배를 타면 내 섬으로 돌아옵니다.

- **이모티콘:** 숫자 1~8 (모바일은 메뉴의 이모티콘 줄). **채팅은 없습니다.**
- **솥 골렘 레이드(최대 8명):** 화학 원리가 곧 규칙입니다.
  1. 증기 방어막 — 설탕·소금을 넣어 **증기 압력 내림** (소금은 이온 2개로 계산)
  2. 과열 제어 — 압력 밸브로 **끓는점**을 조절해 **끓어 넘침**(열원 온도가 끓는점을 넘는 과열의 누적)을 막기. 끓는점은 외부 압력(클라우지우스–클라페롱)과 용질(끓는점 오름, ΔTb = i·Kb·m)로 정해지며, 끓어 넘침은 끓는점 오름과 다른 현상으로 따로 보여 줍니다.
  3. 가스 과압 — **돌턴의 분압 법칙**(P = nRT/V)에 맞춰 기체 캡슐을 정확히 넣기
- 클리어하면 참가자 전원이 코인을 받습니다. 개인 섬의 보관함·퀘스트·저장은 광장과 섞이지 않습니다.
- 연결에 실패하거나 오프라인이면 **연습 모드**(같은 브라우저의 다른 탭끼리만 보임)로 자동 전환됩니다.

### 개인정보 안내

광장에서 다른 플레이어에게 공유되는 정보는 **닉네임(최대 8자, 한글·영문·숫자), 광장 안의 위치·방향, 이모티콘, 레이드 참가 상태**뿐입니다. 본명 대신 별명을 쓰세요.
로그인은 Firebase **익명 인증**이라 이메일·계정 정보를 받지 않습니다. 광장을 나가거나 접속이 끊기면 내 데이터는 지워지고, 오래된 데이터는 화면에서 무시됩니다. 개인 섬의 진행 상황은 내 브라우저에만 저장되고 서버로 보내지 않습니다.

### 서버와 보안의 한계

- 서버는 Firebase Realtime Database(무료 요금제)입니다. 로그인한 사용자만 읽고 쓸 수 있고, 플레이어 데이터는 **본인 항목만** 쓸 수 있게 규칙을 걸어 두었습니다. 닉네임 길이, 좌표·방향·이모티콘 범위, 허용된 필드, 채널 이름(`c1`~`c5`), 레이드 단계 값도 규칙으로 검사합니다.
- **레이드 판정용 서버가 없습니다.** 판정은 참가자 중 한 사람의 브라우저가 맡고, 레이드 데이터는 로그인한 누구나 쓸 수 있습니다. 개발자 도구를 아는 사람이 상태를 조작하거나 코인을 받는 **부정행위는 막지 못합니다.** 친구·학급 단위로 쓰는 수준을 전제로 한 설계입니다.
- 닉네임에 욕설 필터가 없습니다.
- 판정을 맡은 사람이 탭을 백그라운드로 두면 판정이 멈출 수 있습니다(20초 뒤 다음 참가자가 이어받고, 2단계의 과열 누적은 서버에 기록돼 있어 거기서 이어집니다).
- 참가자가 도중에 나가도 레이드는 이어집니다. 나간 사람의 압력 밸브는 합산에서 빠지고, 3단계에서 나간 사람이 가진 캡슐은 접속해 있는 참가자에게 넘어갑니다. 접속해 있는 참가자가 아무도 없는 레이드는 약 1분 뒤 누구든 정리합니다. 시작할 때 인원은 접속해 있는 사람만 셉니다.
- 레이드 **솥 불안정도 게이지**(0~100%): 시간 경과, 증기 압력, 과열 누적, 외부 압력에서 계산하며 실패하는 순간(시간 초과·파열·끓어 넘침) 100%가 됩니다. 레이드 창, 상단 알약, 솥 연출에 같은 값이 쓰입니다.
- 레이드 연출: 솥의 불안정도에 따라 증기 색(흰색→노랑→주황→빨강), 흔들림, 눈과 경고등 깜빡임, 압력계 바늘, 밸브 바퀴 회전, 바닥의 위험 구역 점선 고리, 솥 주변 빛, 화면 가장자리 경고, 상단 알약 색이 바뀌고, 단계가 바뀔 때 섬광과 안내 문구가 나옵니다. 모두 화면에만 그려지며 판정과 서버 데이터에는 영향이 없습니다. 운영체제의 "움직임 줄이기" 설정이면 흔들림과 섬광을 줄입니다.
- 클리어 보상은 레이드마다 한 번만 지급됩니다(마지막으로 받은 레이드 번호를 저장 데이터에 남깁니다).
- 무료 요금제 한도(동시 접속 100명, 월 다운로드 10 GB)를 넘으면 접속이 제한될 수 있습니다.
- 같은 브라우저의 탭들은 익명 로그인 UID를 공유하므로, 플레이어 ID를 `UID_탭마다 새로 뽑은 문자열`로 구분합니다. 이 방식을 쓰려면 `database.rules.json`의 규칙(본인 UID로 시작하는 ID만 쓰기 허용)이 적용되어 있어야 합니다. 새로고침으로 남은 내 이전 접속 데이터는 접속할 때 정리합니다.
- **한 계정은 광장에 한 캐릭터만** 있습니다. 같은 브라우저(같은 익명 계정)에서 창을 또 열어 광장에 들어가면, 나중에 연 창이 광장을 가져가고 먼저 열려 있던 창은 안내와 함께 내 섬으로 돌아옵니다. 익명 로그인은 브라우저 단위라서 다른 기기·다른 브라우저는 서로 다른 계정으로 취급됩니다. 기기와 상관없이 한 사람당 하나로 제한하려면 구글 로그인 같은 실제 계정 로그인이 필요합니다.
- **공동 광장 시각**은 서버 시각에서 계산합니다(저장하는 값 없음, 개인 섬과 같은 속도). 광장에 있는 동안 개인 섬의 시계는 멈추며, 광장의 낮밤 색조는 이 광장 시각을 따릅니다.
- 직접 서버를 쓰려면 `index.html`의 `FIREBASE_CONFIG`를 본인 프로젝트 값으로 바꾸고, Realtime Database·익명 인증을 켠 뒤 규칙을 적용하세요. `FIREBASE_CONFIG`를 `null`로 두면 항상 연습 모드로 동작합니다.

## 저장 방식

진행 상황은 브라우저의 `localStorage`(키 `chemisle_v1`)에 저장됩니다. 침대에서 자거나 30초마다 자동 저장되며, 시작 화면의 **이어하기**로 불러옵니다.
브라우저의 사이트 데이터를 지우면 저장도 지워집니다.

## 구성

```
index.html            게임 전체 (렌더링, 맵, 퀘스트, 실험, UI)
assets/
  tiles.png water.png objects.png buildings.png interior.png   환경·건물·실내 스프라이트
  char_*.png                                                   플레이어·돌턴·상점 주인 스프라이트
  manifest.js                                                  스프라이트 좌표 정보
  make_sprites.py                                              위 PNG와 manifest.js 를 만드는 스크립트
```

그림 리소스는 모두 `assets/make_sprites.py`가 코드로 생성한 **절차적 픽셀아트**입니다. 외부 이미지·폰트는 사용하지 않았습니다.
수정해서 다시 만들려면 Python 3가 설치된 환경에서:

```bash
cd assets
python make_sprites.py
```

## 개발 메모

- 맵은 72×52칸(타일 16px)이며, 화면은 320×200 내부 해상도를 3배 확대해 그립니다.
- 스프라이트를 불러오지 못하면 `SPR.ok=false`로 두고 기존 도형 렌더링을 그대로 사용합니다(전체 대체).
- 충돌·상호작용·퀘스트 데이터와 그래픽 렌더링은 분리되어 있습니다.
- 광장은 별도 장면(`scene==="plaza"`, 50×34칸)이며 `OUT`을 건드리지 않습니다. 네트워크는 얇은 백엔드 인터페이스(Firebase / BroadcastChannel 연습 모드) 뒤에 있습니다.
